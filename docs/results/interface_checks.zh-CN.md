# 答题与工具接口：实际对照检查

这次检查同一批已使用的开发题，先排查接口；不是新 benchmark 的能力排名。54 个题：30 个状态题、24 个身份题。原图通过实际请求补齐。每题比较正常文字回答、正常字母回答，以及三种字母位置下的有限 token 选择。

| 模型 | 正常文字答案与来源标签一致 | 正常字母答案与来源标签一致 | 换字母位置后答案改变的题 |
|---|---:|---:|---:|
| qwen3 | 39/54 | 35/54 | 5/54 |
| qwen25 | 0/54 | 11/54 | 12/54 |
| internvl35 | 36/54 | 36/54 | 10/54 |

能据此确认的三件事：

1. 三个模型都能按要求逐字输出 Supported、Refuted 和 Need more evidence，正常文字答案也都可解析。Qwen2.5 在这 54 个旧题上逐题回答 Need more evidence；这些弃答是模型实际生成的，不是把解析错误补成弃答。
2. InternVL 和 Qwen2.5 的部分原始工具输出是完整 JSON，只缺传输标签。解析器已支持完整单调用 JSON；没有猜工具名、补参数或改变模型选的操作。Qwen2.5 还有要求 finish 却输出 inspect 的记录，单修标签不能解决它。
3. 字母位置或文字/字母回答方式会影响结果，因此有限 token 选择只保留为接口消融，不能代替正常答题基线。

新题上的修复复测使用具体状态声明、正常参考图和分开的提交对象槽位；两个接口使用同一题、预算 12、六回合、相同基础工具。无效回答、工具错误、未结束、真实弃答分别保留。新题尚未独立审核，输出一致性不称为 grounded accuracy。

复现：代码冻结 a86df02，模型和数据哈希见各模型 manifest；原始回答保存在 GPU 节点 p62 的 evaluation/interface-check-v1。完整批处理 24881 已正常结束，资源自动释放。正式新题准入流程见[benchmark 修复说明](../benchmark_v04.zh-CN.md)。
