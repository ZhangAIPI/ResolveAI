# Benchmark 修复：让失败原因能看清楚

当前 v0.4.1 题池有 **478 个题目组合、1,912 个材料释放版本**，保存在 GPU 节点 p62。它们来自 188 张物品状态查询图和 226 个多视角来源序列；身份配对复用这些序列，不能把 478 当成独立实物数量。另有 10 张来自官方训练集的正常参考图，直接复用已有文件。

上一版 872 个组合发现了照片尺寸捷径，已保留为历史诊断材料。新版本对正负身份对照匹配原始尺寸，并对状态声明逐项匹配正常/异常样本数量；没有修改照片像素。

新题目前处于待审核阶段。正式评分入口会检查双人审核记录、证据集合与初始/可获取材料判断是否一致。构造时的四个版本名只记录释放配置；审核后按实际可判断性重新归入 Sufficient、Obtainable、Missing、Unavailable，完整资料库也无法判断的列为 Underdetermined。不强行保持四类各占四分之一。

## 题目具体改了什么

| 问题 | 新题的处理 |
|---|---|
| “有缺陷”太笼统，没有正常标准 | 使用“瓶口有破损”“绝缘层有切口”等具体声明，给一张不同实物的正常参考图 |
| “照片里的物品”可能指错目标 | 公布初始目标区域；模型观察保留原图坐标，审核页面直接画出目标框 |
| 请求菜单暗示双方是同一物体 | subject-A、subject-B 只表示两个提交对象槽位，分别可请求视角 |
| 换视角实际上只是拿到同一预览的原图 | 每个身份题保留四张不同原始照片，两个槽位各两个真实拍摄视角 |
| 不同来源序列被直接当成不同实物 | 同类别配对的物理真假保持未知，等待看图审核 |
| 少了指定原图就机械要求弃答 | 保留其他视角；审核替代充分集合和预览本身能否判断 |
| 图片按不透明 ID 排序，参考/目标顺序混乱 | 保留提交顺序，新获得的照片追加到最后；正常参考先于目标 |
| 解析错误看起来像“需要更多证据” | 正常文字回答无效时记录格式失败；真实弃答、调用错误、轮数耗尽分别记录 |

一道实际状态题是：“提交照片中的瓶子有破损的瓶口。”初始材料包含正常参考与小预览；模型可以检查、裁剪、放大，或请求原图。正常参考来自另一只瓶子，不是目标瓶子的之前照片。若预览已经足够，直接判断也可以。

身份题包括 32 个来源序列内的正身份候选、32 个照片尺寸匹配的跨类别负例、226 个同类别相似物候选。后者尚未赋予“不同物品”的真值。没有匹配尺寸负例的来源正例不进入此轮对照；相关序列仍可参与同类别候选。只有足够四张不同照片的序列进入此轮多视角题池；纹理类 MVTec 样本和没有具体定义的 combined 状态留在历史补充数据中。

## 怎么区分 benchmark 问题和模型问题

先让模型正常回答，并检查它能否复制一个已知合法工具调用。[实际接口对照](results/interface_checks.zh-CN.md)已经发现：完整工具 JSON 缺标签会被旧接口误拒绝，字母解码和选项位置也会影响答案。现在支持完整单调用 JSON，保留模型原始输出，不补工具参数。

在经过审核的同一道题上，分别检查：

1. **初始材料能判吗？** 看不清时回答“需要更多证据”可以是合理判断。
2. **完整可获取材料能判吗？** 若完整材料也无法判断，该题用于不确定性与停止测试。
3. **补齐材料后模型能判吗？** 能判而自主搜索仍失败，才进入搜索策略失败候选。
4. **模型实际拿到了什么？** 看已取材料是否满足任一审核过的充分集合，不只数是否拿到指定原图。
5. **最后哪里失败？** 分开看答案、引用/关系定位、调用格式和是否结束。

新评分记录同时保留“按当前已取材料判断是否合理”和“还有可获取的充分证据未使用”。合理弃答与完成搜证分别报告。全部公共测试素材的轨迹保持测试用途，不进入默认 SFT/DPO 出口。

## 中文逐题审核

审核页面隐藏来源答案，能切换初始材料、该版本全部可获取材料和完整资料库。审核者勾选图片、画原图区域，记录支持/反驳的充分集合；可以添加替代视角或预览集合。

在 GPU 节点的项目环境中运行：

~~~bash
python -m resolveai.review serve \
  /home/cxu-serve/p62/zzh136/experiments/resolveai-poc/benchmark-v041 \
  /home/cxu-serve/p62/zzh136/experiments/resolveai-poc/benchmark-v041/reviews.jsonl \
  --port 8765
~~~

通过现有 SSH 隧道打开 127.0.0.1:8765。每位审核者使用自己的 ID，独立给四个版本的初始/可获取材料判断。页面不显示其他审核者的答案。

两位人工一致、证据集合能解释四个版本的判断时，导出新的可评分子集：

~~~bash
python -m resolveai.review admit \
  /home/cxu-serve/p62/zzh136/experiments/resolveai-poc/benchmark-v041 \
  /home/cxu-serve/p62/zzh136/experiments/resolveai-poc/benchmark-v041/reviews.jsonl \
  /home/cxu-serve/p62/zzh136/experiments/resolveai-poc/benchmark-v041-reviewed
~~~

分歧保留在 pending 中，需要重新独立复核或仲裁后形成一致记录。模型生成的意见不能作为人工审核记录；没有把未审核来源标签自动升级成视觉充分性标签。

## 验证与复现

- 478/478 次指定请求取得正确原图，物品状态保持不变。
- 62 项软件检查通过，包含替代视角、未知身份、审核一致性、区域/时间、自主调用轨迹和训练划分隔离。
- 审核 HTTP 页面、真实图片、源码答案隐藏和非人工记录拒绝经过实际验证；交互 JavaScript 已通过语法检查。
- 三个本地模型的 456 次接口/获取对照已完成，使用冻结代码 6217b47 与历史 v0.4 开发题；后续修复没有混入旧结果。[中文结果](results/repaired_checks.zh-CN.md)用长椅/书和破损瓶子的实际回答解释失败原因。
- 新题池的声明措辞/照片尺寸构造审计通过；对应二分类来源标签上的捷径匹配均为 50%。这不是模型准确率，也不是全面消除来源线索的证明。

[精简题池清单](datasets/benchmark_v04_manifest.json)记录数量与哈希。模型、查询图片、轨迹留在 p62；查询图片直接复用，正常参考直接复用。此轮没有新增自采真实照片，也没有把生成视角作为证据。独立充分性审核、更多预算对照和最终能力结论仍需完成。
