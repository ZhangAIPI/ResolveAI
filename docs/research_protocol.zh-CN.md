# 研究范围与证据链协议

本次收敛以三个**待验证的贡献假设**组织实验，不把增加工具数量或加入 world model 本身当作创新证据。

| 假设 | 环境支持 | 必需实验 |
|---|---|---|
| 物品声明需要身份、状态、时点、区域的显式证据链 | `evidence-chain-v1`，逐子声明评分，关系端点定位 | 与仅答案正确、仅图片引用、区域引用协议对照；独立标注一致性 |
| 不同搜证动作对补足跨图证据有不同作用 | 固定公共历史、世界与后续策略，对比裁剪／检查另一图／特定视角请求／停止 | 固定预算、相同底座与训练量；关闭跨图匹配、索证、证据链、分叉训练 |
| 主动搜证收益能迁移到公开真实多视角物体 | CO3D 原始序列、掩码、相机与划分适配；单独报告仿真和真实结果 | 有足够独立序列、困难负例和经过审核的最小充分证据；按序列置信区间 |

这三个假设仍需与现有研究和实际结果对照，当前实现不能证明论文创新性已经成立。

## 什么算充分证据

`finish` 保留三类结论与原始图片 ID／区域／时点引用，新增可选 `links`。跨图身份或时间子声明的标注要求链接时，单有两个图片引用不够。端点必须来自已经释放的图片，使用原始像素坐标，不能引用隐藏图或派生视图 ID。图片返回公开的物品名称和 camera_view；缩略图保留其原始拍摄视角，策略可以请求该视角的原图，且不会因此获知可获得性或身份真值。

```json
{
  "name": "finish",
  "arguments": {
    "verdict": "Supported",
    "citations": [
      {"image_id": "photo-a", "bbox": [20, 30, 180, 220], "time": "capture"},
      {"image_id": "photo-b", "bbox": [40, 20, 200, 210], "time": "capture"}
    ],
    "links": [{
      "relation": "same_object",
      "left": {"image_id": "photo-a", "bbox": [20, 30, 180, 220], "time": "capture"},
      "right": {"image_id": "photo-b", "bbox": [40, 20, 200, 210], "time": "capture"}
    }]
  }
}
```

链接支持 `same_object`、`different_object`、`earlier_than`、`same_time`。身份与同时间关系可交换端点；先后关系有方向。与独立标注比较时，端点 IoU 默认至少 0.5，不能用整图框代替局部身份对应。区域充分性使用精确覆盖并集，重复引用不会提高覆盖率。

私有标注为每个子声明记录 truth（Supported／Refuted／uncertain）及可替代的最小充分证据集合。支持合取声明必须覆盖所有为真的子声明；反驳只需覆盖一个确实为假的子声明。错误的额外关系也会使证据链不充分。子声明真值不确定时不能强行判支持；一个其他子声明的决定性反例仍可反驳整个合取声明。环境不向策略返回私有证据缺口、关系真值或评分。

物理真假与案件目标分开：某个声明实际为真，但完整可获得证据库无法满足任何充分证据集合时，新协议的案件目标是 Need more evidence。支持要求所有子声明的某个充分集合可获得；反驳只需一个决定性反例集合可获得。这个目标来自私有标注，候选标注未经审核时仍只作为协议集成代理。

`region-time-v1` 和旧图片集合评分保留兼容。默认 SFT／偏好出口只接受 reviewed 的区域或证据链协议；未经审核的 CO3D 候选和 MVTec 图片集合代理不能自动进入正式监督。

## 如何比较动作与 CounterCredit

[`compare_actions`](../src/resolveai/branching.py) 从同一公共历史分叉真实工具调用，固定世界、预算、总步数上限和后续策略。它记录首个动作及整条轨迹释放了哪些原图，只导出首个不同的 assistant 动作用于偏好训练。模型客户端只接收公共消息和图片；分叉与终局评分属于可信训练器。

同一个可见前缀可能对应可获得或不可获得的隐藏版本，不能用事后失败信息教策略提前知道提供方无法提交。默认偏好出口会过滤在失败尚未可见时、仅凭费用偏好提前弃答的动作对。将来需要按相同可见前缀汇总可获得性版本的期望收益；在实际失败反馈出现之后可以监督停止。

确定性生成可直接比较；随机策略必须逐分支重置同一随机种子并记录。对比应报告补足哪些子声明、正确且证据充分的结论、无依据结论、失败请求和分开的工具／索证费用，不只看工具调用数量。

[CounterCredit 原论文](https://arxiv.org/abs/2609.22910) 在同一调用前缀比较立即回答、真实裁剪和同尺寸随机裁剪，分别检查调用必要性和返回像素是否被使用；其主工具设定是从单张原图裁剪。因此“能分叉”或“更省工具”本身不足以与它拉开差距。

需要分别报告：

1. 相同裁剪工具设定下的原方法复现，按论文定义实现答案打分与训练目标。
2. 同工具池下的 **adapted CounterCredit**。检查另一图、新视角与请求失败需事先定义类型、分辨率、来源和成本匹配的对照返回；没有可靠匹配时不宣称完成该动作的因果归因。
3. 我们的跨图证据链目标，在相同训练预算下检验身份连接、关键视角释放和停止判断的增益。

若用终局证据链正确性代替其 gold-answer policy score，或用 DPO 代替其 GRPO，必须标为适配版本。当前没有完成 CounterCredit 训练对照，不能宣称优于它。

## 公开数据与 world model

- **CO3D**：保留 [官方序列、相机、帧时间与划分](https://github.com/facebookresearch/co3d)。按完整序列隔离四种案件版本，同一视频内的帧时间不是损坏前后标签。不同序列不自动视为不同实物。候选同物体标签来自序列来源，掩码来自官方数据，最小充分证据和可获得性仍需独立审核。
- **MVImgNet**：有大规模真实多视角，但 [官方下载](https://github.com/GAP-LAB-CUHK-SZ/MVImgNet) 需要申请，当前先使用可直接获取的 CO3D。
- **MVTec AD**：保留为异常识别与区域定位补充；不构造不同实物的真实前后变化。既有图片集合代理成绩与新证据链成绩分别报告。
- **仿真**：损坏前后变化与困难身份负例可由状态控制产生。当前单桌场景是未独立审核的接口演示，不能代表训练集规模或研究结果。

核心 world model 使用不可变物体状态与预先渲染／拍摄的证据库。真实数据请求只释放已有照片，不能声称实际新拍摄了视角。仿真可离线增加相机渲染，但请求不会改变物体状态、时点或损坏。裁剪、放大与 OCR 不产生独立事实。

生成式 world model 可作为后续独立消融：从可见信息预测有价值的拍摄方向，输出标为 imagined，不进入原始证据引用与充分性评分。只有身份、状态一致性及选视角增益得到验证后才考虑加入；当前没有新增生成式 world-model 工具。

CO3D 适配命令（原始数据与模型存放在仓库之外）：

```bash
python -m resolveai.co3d_subset /path/to/co3d \
  --categories chair cup bottle book car bench --families 300 --views 16
python -m resolveai.co3d_data /path/to/co3d /path/to/cases \
  --categories chair cup bottle book car bench --families 300 --views 8 --split test
```

输出 cases、来源清单、数据清单和待审核标注。官方测试序列可提供的已知前景视角数量不同；每族保留实际可用的 2–8 个视角，不重复图片凑数。原图优先硬链接，保留小缩略图，避免重复中间文件。声明是正身份候选，因此其准确率不能作为平衡身份验证成绩；同类别困难负例和两位独立标注者的审核仍是正式 benchmark 的缺口。CO3D 使用 CC-BY-NC-4.0，保留官方许可和出处，不把数据或模型权重提交 Git。

按需读取只下载目标照片与掩码。元数据分包使用官方 SHA256 校验；HTTP range 成员使用 ZIP CRC32 校验并记录内容 SHA256，没有读取整包时不声称通过整包 SHA256 校验。

本轮已冻结 300 个官方测试序列、1,594 张原始照片和 1,200 个案件版本，见 [候选数据清单](datasets/co3d_candidate_manifest.json)。每族实际 2–8 个视角，六个类别各 50 个序列。序列是统计分组单位，不能据此保证不同序列一定来自不同实物。
